## Statistics components and workflow

Reviewed GitHub Readme Stats, lowlighter/metrics, github-readme-activity-graph, and Platane/snk. Selected only GitHub Readme Stats via its recommended Action route. A direct public-endpoint request returned valid SVGs during setup; the final page serves committed SVGs and does not depend on that endpoint at view time.

The recommended Action repository has moved to `stats-organization/github-readme-stats-action`. Its documentation, Action definition, and entry point were inspected. The workflow pins the Action and checkout to verified commit SHAs.

- Workflow: [profile-cards.yml](../.github/workflows/profile-cards.yml).
- Daily at **10:17 Asia/Shanghai** (02:17 UTC), manual dispatch, and pushes changing the workflow.
- Repository-scoped `GITHUB_TOKEN`; no personal access token or new secret.
- `contents: write` is used to commit only the two public SVG cards.
- Data-fetch errors fail the workflow, retaining the last committed cards.
- SVG validation checks XML, expected root, script elements, and error-card text.
- Concurrency prevents simultaneous refreshes; timeout is 12 minutes.
- Private repositories and private contribution details are not intentionally queried by the cards.
- GitHub's existing contribution calendar supplies contribution activity; no duplicate graph.
- Language proportions include vendored/dependency code and do not measure proficiency.
